# Upstream documentation snapshot — USDA FAS Global Agricultural Trade System

Source of truth for every endpoint wrapper (ADR-0003). The files in this directory are
written by `scripts/refresh_upstream.py` (`/refresh-upstream`) from the documents in the
table below and refreshed deliberately by PR, so that changes show up as diffs. This
file is generated by the same script. Nothing here was edited by hand.

## Attribution

None stated: neither document's `info` names a licence, terms of service or a contact,
and neither document carries a copyright line. The documents' text is reproduced here as
this package's reference (ADR-0003); an objection from the publisher is met by replacing
it with a summary that keeps the names and semantics the wrappers rely on.

## How this is captured

The FAS Open Data Services portal, https://apps.fas.usda.gov/opendatawebV2/, documents
three APIs of USDA's Foreign Agricultural Service: ESR, GATS and PSD. It is an Angular
app whose page is a shell without documentation text. Its Swagger window loads the
Swagger 2.0 document
https://apps.fas.usda.gov/opendatawebV2/assets/swagger/swagger.json. That URL comes from
sdk-usda-psd, the first FAS package of this family: on 2026-10-23 its session found it
in the Swagger UI configuration of a session-local scratch copy of the portal's
JavaScript bundle, since deleted. The script never downloads the bundle, since it embeds
the portal's own api.data.gov signup-widget key, and this file records only its file
name: as of this run the portal page loads `main.6da18f8b4fa8a2baed40.js`.

The API also serves its own Swashbuckle document,
https://apps.fas.usda.gov/OpenData/swagger/docs/v1, which the classic Swagger UI at
https://apps.fas.usda.gov/opendata/swagger/ui/index loads; the script reads that URL
from the UI page's `rootUrl` and `discoveryPaths`. Both documents are kept because they
are two upstream statements of the same API that need not agree on how it is reached. As
fetched, their GATS parts differ in `host` and `securityDefinitions`; only the portal
document has `security`; only the backend document has `basePath`; they agree in
`swagger`, `info`, `schemes`, `paths` and `definitions`.

Both documents cover ESR, GATS and PSD, and ESR and PSD get their own packages in this
family (sdk-usda-esr, sdk-usda-psd), so each file here holds the GATS part only: every
top-level field verbatim and in upstream order, `paths` reduced to the keys starting
with `/api/gats/` and `definitions` reduced to those the kept paths reference, directly
or through other definitions; each document's row counts the paths kept and dropped, per
prefix, and the script stops unless the paths it leaves out fall under exactly
`/api/esr/` and `/api/psd/`. It writes the part with `json.dumps(indent=2,
ensure_ascii=False)` in upstream key order, with LF line endings and a final newline,
and stops unless the full document re-serialised the same way reproduces the fetched
text up to line endings, so each file is the upstream text with the other APIs cut out.
Bytes and sha256 in a document's row are those of the full document as fetched, so a
change anywhere in it shows here. Both files are JSON, so no table is kept as HTML.

Pages without documentation text get no file, only a row with their HTTP status and the
size and sha256 of the body: the portal page and the classic Swagger UI, both
client-rendered shells; the GATS application, which redirects to a screen-detection page
whose one script sends the browser on; and the FAS data page, which the CDN edge
answers, for this script, with 403 Access Denied and a body that carries a per-request
reference number, so that row records neither size nor sha256. Against the same
upstream, two runs write byte-identical files under `openapi/`, and this file differs
only in its Fetched column.

Fetched is the UTC time the run started, in ISO 8601 with an explicit Z, the same for
every row; Last-Modified is the HTTP header in UTC, ETag as sent. Requests go one at a
time, identified as `xippios-usda-gats refresh_upstream (+https://github.com/xippios)`;
no API key is sent or read.
